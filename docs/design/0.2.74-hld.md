# Weft 0.2.74 — High-Level Design

Status: proposed (Falconry plan; implementation starts on "aloft").
Scope: everything agreed in the 2026-11-22 planning session. Ships as one release, directly on
`main`, with **no backward compatibility** for older laptops, phones or on-disk files.
Companion: [0.2.74-lld.md](0.2.74-lld.md) (modules, schemas, state machines, protocol, tests).

## 1. Problem

Weft lets a phone drive Copilot CLI sessions running on a laptop. Three classes of problem showed
up in real use on 2026-11-21/22:

1. **Silent connection loss.** A session (`weft uodat3s2`) ran `extensions_reload` six times in
   two seconds. The final Weft instance reloaded the same channel identity, never logged
   `pairing.ready`, and retried its relay subscription silently for 4.5 hours
   (`~/.weft/sessions/0146d2fb….log`; `activeRuntime.mjs` `connectRelayWithRetry` logs failures
   only for non-handoff sessions). Its presence record still said `active`. The phone showed
   "Connecting…" with no way forward although Station was online.
2. **Recovery the user cannot reason about.** The phone offers *Reconnect* (phone-side socket
   retry only) and *Resume on laptop* (Station opens the session) and leaves the user to guess. Pull
   to refresh does nothing offline. A running Station or session keeps old code after
   `weft update`, so fixes silently do not apply (the 0.2.71 effort-level fix needed a manual
   Station restart).
3. **A tangled laptop model.** Session state is split across six stores
   (`runtimes/v1/*/presence.json`, `attached-sessions.json`, `pending-sessions.json`,
   `launch-operations/`, `launch-reservations/`, `launch-identities/`), two coordinator layers,
   and status vocabularies that never reconcile (`dormant|activating|active|degraded` vs
   `pairing-ready|controller-conflict|endpoint-refresh-needed`). Cleanup follows five different
   rules. No component can answer "is this session reachable from the phone, and if not, why?"

Plus a set of UI asks: a clearer header and menu, faster session controls, pairing from the phone's
own camera, and a `weft start` that always ends with a working Station.

## 2. Goals

| # | Goal | Measured by |
|---|---|---|
| G1 | A session that loses its phone link recovers **without user action** whenever the laptop and Station are healthy | Acceptance test A1 (6 reloads in 2 s) reaches `linked` with no tap |
| G2 | When recovery needs the user, **one action** with honest, specific progress | Recovery bar copy table (§6.4) covers every failure reason |
| G3 | **One writer per saved Copilot session**, always | A2: two open requests for one session during reload + Station restart yield one writer |
| G4 | Phone, Station and Control Center **agree** on health | One shared projection `sessionHealth()` used by all three |
| G5 | `weft start`, Control Center and `weft update` **always end with current, running code** | A8: update while Station runs old code → Station restarted on new code |
| G6 | Fewer concepts: 6 session stores → 2, ~17 session modules → 9 | File inventory in LLD §2 |
| G7 | Phone UI asks shipped (header, menu, gestures, pairing links, recovery bar) | UI acceptance list in LLD §9.2 |

## 3. Non-goals

- Changing encryption, pairing trust or the relay servers.
- Moving Copilot's own session store or history.
- Attaching to (re-focusing) an existing terminal window; Weft can open terminals, not adopt them.
- Strict remote exclusivity on the relay (the relays broadcast to all subscribers by design; see
  `relayServer.mjs:17-48` and the Supabase broadcast policy).
- Supporting older laptops/phones/files. Mismatches are **rejected explicitly**, never silent.

## 4. Principles

1. **Facts, not self-reported health.** A wedged process cannot report that it is wedged. Each
   party records what it knows; health is *derived*.
2. **One writer per record.** Every file has exactly one writing component.
3. **Never guess ownership.** If the laptop cannot prove who writes a saved session, it stops and
   says so (`owner-unknown`), rather than launching a second writer.
4. **Repair before restart, restart only with proof, destroy only with consent.**
5. **Bounded everything.** Every connection attempt has a deadline and can be cancelled; every
   repair has a budget; every retry is logged.
6. **Stale work cannot win.** Every async continuation is fenced by a generation number.

## 5. Architecture

```
              PHONE  (Android app / web app)
              │ device link (one per laptop)          │ session link (one per session)
              ▼                                       ▼
 ┌─────────────────────────────── LAPTOP ───────────────────────────────────────┐
 │ STATION  (station.mjs, one background worker, ensureStationRunning())       │
 │   • phone control: list · open(new | existing) · session health · cancel     │
 │   • openSession → openRequests → terminalLauncher                            │
 │   • supervisor: immediate probes + 15 s sweep → repair / clean               │
 │   • observations in memory only                                              │
 │          ▲ local pipe (sessionControl: capability-authenticated, fenced)     │
 │ ┌────────┴──────────────────────────────────────────────────────────────┐   │
 │ │ COPILOT SESSION + sessionHost                                           │   │
 │ │   transition queue: activate · reload · repair · switch · takeover · stop│  │
 │ │   sessionLink: abortable connect → handshake → app-ready ──────────────┼───┼─► relay ─► phone
 │ │   writes facts → ~/.weft/sessions-live/<runtimeId>.json                 │   │
 │ └─────────────────────────────────────────────────────────────────────────┘   │
 │ open requests → ~/.weft/requests/<id>/   (per-session lock, idempotent, honest outcome) │
 └────────────────────────────────────────────────────────────────────────────────┘
   shared/sessionHealth(facts, observations) → label + reason  (phone · Station · Control Center)
```

### 5.1 Owners

| Owner | Owns (writes) | Observes | Never does |
|---|---|---|---|
| **Session** (`sessionHost` + `sessionLink`, inside each Copilot process) | its live record; its link lifecycle; controller authorization | its own transport | start or resume other sessions |
| **Station** (`station`) | open requests; per-session open locks; in-memory observations; repair attempts | session records, process identity, pipe probes | write a session's record; resume without proof the previous writer stopped |
| **Phone** | its own connection and handshake observations | session link traffic; Station's health answers | decide activate vs resume |

### 5.2 Identities

| Identity | Guards |
|---|---|
| `(storeAuthority, sessionId)` | the saved session; **the one-writer key** |
| `runtimeId` + `generation` | one Weft instance inside one Copilot process; bumps on reload |
| `link.generation` | one relay connection + handshake; bumps on every reconnect/reset |
| `controllerRevision` | which phone controls the session; bumps on takeover |
| `endpointRevision` (Dev Tunnel) | the laptop's reachable address; separate from link identity |

## 6. Key designs

### 6.1 Session link (fixes the incident at the root)

- One **transition queue** per session serializes activate, reload, repair, transport switch,
  takeover and shutdown. Nothing overlaps.
- Every connection attempt carries an **AbortSignal and a deadline** (30 s). Each failure is
  logged (rate-limited) and written to the record (`attempt`, `lastError`, `deadlineAt`).
- Every async continuation checks `link.generation`; results from a retired generation are
  dropped. A retired instance rejects prompts and approvals.
- **Ready means end-to-end ready**: cryptographic handshake, then an app-level `link_ready`
  exchange after handlers attach, then catch-up. Today's ACK is sent before relay attachment
  finishes (`shared/pairing.mjs:229-351`), which is why "connected" could be false.
- Reload keeps the same channel identity (today's design, unchanged) but now cancels and awaits the
  old instance's pending transport before the new one connects.

### 6.2 Health projection

`sessionHealth(record, observations, now)` is a pure shared function. Output: `{ label, reason,
observer, freshAt }`.

- Labels: `dormant · connecting · waiting · linked · stalled · ending · gone`.
- Reasons: `phone-away`, `link-stuck`, `unresponsive`, `owner-unknown`, `controller-conflict`,
  `endpoint-changed`, `config-error`, `shared-outage`, `needs-attention`.
- Silence while the phone is in the background (`phoneWatching:false`, the existing attention
  lease) is `phone-away`, never `stalled`.

### 6.3 Station supervisor

- Inputs: immediate probe on open/recovery requests + a 15 s reconciliation sweep (no overlapping
  rounds, bounded concurrency). File-watch hints are deferred (unreliable on Windows).
- Classifies each live session into one failure class and acts:

| Class | Detected when | Action |
|---|---|---|
| unresponsive | pipe probe misses its deadline twice | report; resume only via an explicit open request with proof |
| link-stuck | `connecting` past `deadlineAt`, runtime responsive | `resetLink` over the pipe, ≤2 per episode |
| phone-away | `phoneWatching:false` | nothing |
| shared-outage | ≥ all linked sessions stuck at once | repair shared transport once, not each session |
| config-error | `lastError` is a configuration/auth error | surface the error; no retries |

- After laptop sleep or timer drift > 60 s: one grace sweep that only re-observes.
- Cleanup owner: deletes records only after proving process death (pid + start time); daily prune
  of finished requests, catch-up cache and logs within budgets.

### 6.4 Open requests and recovery

- The phone asks **`open(new: project)`** or **`open(existing: sessionId)`**; Station chooses
  activate, resume or start. Callers never pick the mechanism.
- Requests keep today's correctness mechanisms: per-session lock, idempotency fingerprint,
  monotonic revision, staged progress and honest `outcome-unknown`.
- **Reconnect never restarts silently.** Order: reconnect phone → repair in place (automatic) →
  resume in a new terminal **only after proving the previous writer stopped** → destructive
  restart or takeover **only with confirmation** bound to `runtimeId` + `controllerRevision`.
- The phone's recovery bar sits above the composer and shows the derived reason in plain words
  (copy table in LLD §7.3). Pull-to-refresh runs the same action.

### 6.5 `ensureStationRunning()`

One operation used by `weft start`, Control Center and `weft update`:
compare build version **and** installation identity → under the management lock, disable
supervision → stop the exact worker → confirm exit → start → wait for local readiness (network
readiness reported separately). Preserves crash history and device trust. A Station waiting on the
network is not "unresponsive".

### 6.6 Phone UI

- Header: the Weft mark in a tile is the menu button on every screen; title = session name or
  folder; Scan moves into ⋯ and the drawer.
- Session controls: open by swiping up anywhere on the composer; close by dragging down anywhere
  on the sheet; Medium as fallback default effort when the CLI omits defaults.
- ⋯ menu: line icons; Rename · Pin · Archive | Scan QR | **Remove from this phone** (red); Debug
  only in Debug mode; "Reload history" removed (pull-to-refresh does it).
- Pairing links: laptop QR is `https://useweft.netlify.app/pair#<code>`; the phone's camera opens
  the Android app (App Links) or the web app; in-app scan and paste accept both forms.

## 7. Key decisions

| Decision | Chosen | Rejected | Why |
|---|---|---|---|
| Health source | facts + shared projection | one self-reported status | a wedged session cannot report it is wedged |
| Station observations | in memory | persisted | rebuilt on restart; nothing to go stale |
| Supervisor trigger | probes + 15 s sweep | fs.watch only | watch misses wedges; unreliable on Windows |
| Recovery escalation | automatic repair; resume only with proof; confirm destructive | auto-resume on timeout | a 5 s network blip must not fork a writer |
| Ambiguous reload handover | cancel + fence (ship); channel rotation | always rotate | rotation is deferred until test A1 shows cancel+fence is insufficient |
| Naming | `session*` everywhere | `chat*` | repository, SDK and UI already say "session" |
| Compatibility | none; explicit "update Weft" | adapters | user decision; removes `sessionCompatibility.mjs` |
| `registryFile.mjs` | keep separate | fold into session registry | also used by the Dev Tunnel registry |

## 8. Risks

| Risk | Mitigation |
|---|---|
| Big-bang release on `main` | acceptance suite A1–A8 + full CI via manual Release; laptop-only targeted tests |
| Old sessions still running old code after update | `ensureStationRunning` restarts Station; running sessions show "Update Weft in this session" until reloaded; old records honored until their processes exit |
| Generation fencing bugs | every fenced path has a test that injects a late result |
| App-level ready adds a round trip | one extra encrypted message on connect; negligible |
| Station absent | sessions retry and log on their own; phone shows "/weft again" guidance |

## 9. Rollout

1. Build items on `main` in dependency order (LLD §10).
2. Targeted local tests only; full suite via **Actions → CI (full)**.
3. Bump to 0.2.74, **Actions → Release (production, all)**.
4. `weft update` on the laptop → `ensureStationRunning` restarts Station on 0.2.74 → reload the
   extension in open sessions.
5. Install the APK; verify acceptance cases on the phone.
