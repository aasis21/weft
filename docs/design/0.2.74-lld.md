## 3. On-disk state (`~/.weft/`)

### 3.1 `sessions-live/<runtimeId>.json` — written only by that session

```json
{
  "schema": 1,
  "session":  { "storeAuthority": "sha256:…", "sessionId": "0146d2fb-…" },
  "run":      { "runtimeId": "d1018223-…", "generation": 3,
                "pid": 14596, "processStartedAt": 1795376556948,
                "terminalInstanceId": "cbab6fb4-…", "version": "0.2.74",
                "openedBy": { "kind": "station", "requestId": "open-230c…" } },
  "control":  { "pipe": "\\\\.\\pipe\\weft-session-be25…" },
  "link":     { "generation": 7, "state": "connecting",
                "attempt": 4, "deadlineAt": 1795376600000,
                "lastError": { "code": "subscribe-timeout", "at": 1795376590000 },
                "controllerRevision": 2, "lastPhoneContactAt": 1795376500000,
                "phoneWatching": false, "endpointRevision": 1 },
  "offer":    { "expiresAt": 1795377000000 },
  "updatedAt": 1795376590000
}
```

- `link.state`: `dormant | connecting | waiting | linked | ending`. (`stalled` is never written; it
  is derived.)
- Sibling `<runtimeId>.key`: 32-byte capability, mode 0600 (best-effort on Windows).
- Writes: temp file + rename. Triggers in §4.1. Throttles: failures ≤ 1 write / 10 s; contact
  ≤ 1 write / 60 s; state changes immediate.
- Deletion: on clean shutdown after the transition queue drains; otherwise by the supervisor after
  proving death (`pid` alive **and** `processStartedAt` matches → alive).

### 3.2 `requests/<requestId>/` — written only by Station

`request.json`:

```json
{
  "schema": 1, "requestId": "open-230c…", "revision": 9,
  "fingerprint": "sha256(target|mode|requester)",
  "requester": "phone:81cec90e-…",
  "target": { "existing": { "storeAuthority": "sha256:…", "sessionId": "0146d2fb-…" } },
  "options": { "permissionMode": "default", "title": "weft updates" },
  "stage": "awaiting-runtime",
  "outcome": null,
  "result": { "action": "resume", "runtimeId": "…", "pid": 13972 },
  "failure": null,
  "createdAt": 0, "updatedAt": 0, "dispatchedAt": 0, "finishedAt": 0
}
```

- `stage`: `accepted → resolving → [awaiting-confirmation] → dispatching → awaiting-runtime →
  preparing-link`.
- `outcome`: `done | failed | cancelled | outcome-unknown`.
- `identity.json`: channel id + laptop keypair + operation owner token for a launched session
  (0600). Read by the new session through `WEFT_IDENTITY_FILE`.
- `requests/.by-session/<storeAuthority>-<sessionId>.lock`: exclusive lock while any non-terminal
  request targets that session. Recovered on Station start by re-reading non-terminal requests.
- Retention: delete 3 days after `finishedAt`, unless a live record's `openedBy.requestId`
  references it.

### 3.3 Unchanged

`weft.config.json`, pairing/trust files, `session-streams/`, `sessions/*.log`, `station.log`,
`connections.json` (diagnostics only), `background-*.json`.

### 3.4 Removed on first 0.2.74 start

`runtimes/`, `attached-sessions.json`, `pending-sessions.json`, `launch-operations/`,
`launch-reservations/`, `launch-identities/`, `.launch-locks/` — **only entries whose processes
are dead**. Entries owned by live old-version processes are left until those processes exit, and
`openSession` treats them as `owner-unknown` (never launches a second writer).

## 4. State machines

### 4.1 Session link (in `sessionLink`, serialized by the transition queue)

```
          activate()                     handshake ok
 dormant ───────────► connecting ──────────────► waiting ─────────► linked
    ▲                  │  ▲  │ subscribe ok     (QR / offer)  link_ready │
    │                  │  │  └──────────────────────────────────────────┘
    │     deadline/err │  │ retry (backoff 1.5 s ×2 ≤ 15 s, deadline 30 s per attempt)
    │                  ▼  │
    │              (attempt++, lastError, log)
    │
    │ resetLink() / reload / transport switch / takeover: bump link.generation,
    │ abort pending attempt, await close, → connecting
    │
 stop(): → ending → record deleted
```

Rules:
- `link.generation` increments on every entry to `connecting`. Every awaited step captures it and
  returns early if it changed.
- Exactly one transport object is live per generation (pending or active), tracked and closed on
  generation change.
- `linked` requires: handshake ACK **and** `link_ready` from the phone after handlers attach.
- Handoff sessions (launched by Station) retry indefinitely (the phone is waiting on that channel)
  but every failure is logged; after 60 s of failures the session prints one line:
  "Weft: can't reach the relay (‹code›). Retrying." (repeat at most every 10 min).

### 4.2 Open request (in `openSession` + `openRequests`)

```
accepted → resolving ─┬─ exact live runtime, responsive ───► (activate | repair) → done
                      ├─ live runtime, other controller ────► awaiting-confirmation ─confirm→ takeover → done
                      ├─ live process but unprovable owner ─► failed(owner-unknown)
                      ├─ no live writer (proven) ───────────► dispatching → awaiting-runtime → preparing-link → done
                      └─ target missing ────────────────────► failed(not-found)
 any stage: cancel → cancelled  (after dispatching: cancelled + result says the session may be running)
 lost acknowledgement / Station crash mid-dispatch → outcome-unknown, reconciled on next start
```

`done` = a responsive runtime exists for the target **and** its link reached `waiting` or
`linked`.

### 4.3 Supervisor episode (per runtime, in Station memory)

```
ok ──(link-stuck detected)──► repair#1 ──fail──► repair#2 ──fail──► needs-attention
 ▲                              │ok               │ok                    │ (reported; no more auto repair
 └──────────────────────────────┴─────────────────┘                     │  until the link changes state)
```

Episode resets when the record's `link.generation` advances and reaches `linked`.

## 5. Laptop components

### 5.1 `sessionHost`
- `start(session)`: build identity (handoff file → reload identity → fresh), write the record
  (`dormant`), start `sessionControl` server, register `/weft`.
- Transition queue: `enqueue(kind, fn)`; kinds `activate | reload | resetLink | switchTransport |
  replaceController | stop`. One at a time; `stop` drains then rejects new work.
- On reload: `stop({ keepIdentity: true })` in the old instance awaits link teardown before
  returning the reload identity.

### 5.2 `sessionControl` commands (pipe, JSON lines, capability in first frame)

| Command | Args | Effect | Idempotency |
|---|---|---|---|
| `probe` | — | `{ runtimeId, generation, link, version }` | read-only |
| `activate` | `{ requestId, identityRef? }` | enqueue activate | keyed by `requestId` |
| `resetLink` | `{ opId, expectGeneration }` | enqueue reset if `link.generation == expectGeneration` | keyed by `opId`; stale generation → `stale` |
| `replaceController` | `{ opId, expectControllerRevision, phonePub }` | enqueue takeover | revision-fenced |
| `quiesce` | `{ opId }` | enqueue stop | keyed by `opId` |
| `traffic` | — | diagnostic counters | read-only |

All commands: 5 s client deadline; a timed-out call is **not** assumed cancelled; Station re-probes.

### 5.3 `sessionRegistry`
- `writeRecord(patch)` (session side): merge, validate, atomic write, throttle.
- `scan({ verify })` (Station side): read all records, batch-verify `pid + processStartedAt`,
  group by `(storeAuthority, sessionId)`, return `{ sessions: [{ key, runtimes[] }], deadIds }`.
  Two live runtimes for one key → `owner-conflict`.
- `ownerOf(key)`: live runtime for the key **or** a live Copilot process proven to hold it (from
  the launch result pid + start time) → else `none` only if proven; otherwise `unknown`.

### 5.4 Station supervisor (in `station.mjs`)
- `sweep()` every 15 s, single-flight, ≤ 4 concurrent probes, 5 s per probe.
- Inputs: `registry.scan()`, `probe` results, `now`, last sweep time (drift detection > 60 s →
  grace sweep).
- For each runtime compute `sessionHealth(record, observation, now)`; act per HLD §6.3 table.
- Shared-outage rule: if ≥ 2 sessions and all `linked/waiting` ones turn `link-stuck` within one
  sweep, run one transport health check and skip per-session repairs.
- Writes nothing to session records; holds `Map<runtimeId, {probe, episode}>` in memory.
- Exposes `health(sessionId)` for the phone `session_health` request and Control Center.

### 5.5 `ensureStationRunning({ reason })`
1. Acquire the management lock (existing `withManagementLock`).
2. Read worker status (pipe) and scheduled-task/launchd definition.
3. Decide:

| Observed | Action |
|---|---|
| running, same `version` + `installId` | return `already-running` with summary |
| running, older version or different `installId` | disable supervision → `quiesce` → confirm exit (≤ 10 s) → stop task → start |
| task running, worker silent > 15 s locally (network wait excluded) | force stop exact pid (verified start time) → start |
| crash-looping | start once; on repeat crash return last error + log path |
| foreground instance holds `listener.lock` | report pid; replace only when invoked from CLI with a TTY confirmation |
| stopped | start |

4. Wait for local readiness (pipe answers) ≤ 30 s; report network readiness separately.
5. Callers: `weft start` (prints staged lines), Control Center primary button, `weft update`
   (after install, if a worker runs older code).

### 6.4 Pairing links (item 4)

### 7.3 Recovery bar and pull-to-refresh (item 7)
- `RecoveryBar` replaces the offline banner; one row (max two lines), attached to the composer
  top, same width/margins; 2 px progress edge; tap text → step pop-over with device name.
- Single action `recover(sessionId)`:
  1. If the session link is `connecting` > 15 s or closed: retry the socket for ≤ 5 s.
  2. If a Station device for this session is reachable: `open_session({ existing })` and stream
     `lifecycle_status` into the bar.
  3. Otherwise: show the no-Station guidance.
- Pull-to-refresh: `linked` → fetch recent turns; otherwise `recover()`.
- Stale running tool rows: after reconnect, catch-up replaces any `running` item older than the
  last laptop turn with its final state.

| done | Back online and ready | — (fades 3 s) | Reconnected to the running session / Opened in a new terminal. |
